هدف

Agentic Flow بین هدف Task، Implementation، Receipt، وضعیت عملیاتی پروژه و Authority تفاوت روشن می‌گذارد. واقعیت Durable پروژه در Repository می‌ماند و Context روزمره Agent کوچک و قابل‌تعویض است.

Adoption با ZIP قابل‌حمل

python3 scripts/build_agent_bundle.py
# ZIP را داخل پروژه به صورت .agentic-flow/ Extract کنید
# Agent از .agentic-flow/START_HERE.md شروع کند

اگر Coding از قبل فعال است، قبل از هر Mutation جدید از docs/agent/MIDSTREAM_ADOPTION.md استفاده می‌شود. Branch، HEAD، Dirty Paths، Task، Testهای قبلی و Environment Mutationها Snapshot می‌شوند و کار معتبر موجود دور ریخته نمی‌شود.

Project Baseline

یک فایل کوچک مانند .agentic/PROJECT_PROFILE.yaml Requirementهای Testing، Readiness، Environment Permission و Controlهای عملیاتی را مشخص می‌کند. این فایل Reality را ثابت نمی‌کند؛ موارد Missing یا Unverified به‌صورت Gap می‌مانند. Exception موقت با Owner و Expiry ثبت می‌شود و Baseline بی‌صدا تغییر نمی‌کند.

چرخه Task و Evidence

REQUEST → DRAFT → REVIEW → AUTHORIZATION در صورت نیاز → APPLY → VERIFY → Independent Closure

برای Task مهم، قبل از Implementation باید DoD قابل مشاهده، Claimهای Closure، حداقل Receipt هر Claim، Test/Environment لازم و شرایط STOP مشخص شوند. Claim نباید از Receipt قوی‌تر باشد.

Test و Environment

برای Claimهای مهم Test Design قبل از Implementation انجام می‌شود، ولی strict TDD برای هر تغییر کوچک یا Exploratory اجباری نیست. Testهای Load-bearing در صورت نیاز با Mutation/Path Proof اثبات می‌شوند.

LOCAL/HERMETIC → EPHEMERAL TEST → SHARED TEST → STAGING/PRODUCTION-LIKE → CONTROLLED CANARY/PRODUCTION READ → PRODUCTION MUTATION

Agent پایین‌ترین Environmentی را استفاده می‌کند که Claim را ثابت کند. درخواست دسترسی قوی‌تر به معنی Authorization نیست.

Production Engineering

  • Delivery از Source و Build تا Immutable Artifact، Deploy، Health و Rollback.
  • Security-first در Design، Coding، CI/Supply Chain و Runtime.
  • Metrics/Logs/Traces، SLI/SLO و Alertهای قابل اقدام.
  • Data Durability با RPO/RTO، Backup/PITR/Retention و Restore Proof.
  • Troubleshooting، Runbook و Release Correlation.
  • AI-safe Log Analysis: Log Structured/Redacted/Bounded و متن Log به‌عنوان Untrusted Data.
  • Resilience/Chaos فقط با Maturity، Steady State، Blast Radius و Abort/Recovery.
  • Pattern و معماری قابل تغییر متناسب با Boundary و پیچیدگی واقعی.

Backup Enabled به معنی Recoverability نیست؛ Restore همان Receipt است.
