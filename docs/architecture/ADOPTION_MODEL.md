# Adoption Model

**Architecture reader**  
**Version:** 1.0  
**Updated:** 2026-09-09T11:30:00Z

Agentic Flow supports three adoption modes without changing its core authority model.

## New / idle repository

Bootstrap the project profile, discover build/test/deploy/operability, generate the minimum vendor adapter, and validate the operating layer before product work.

## Existing mature repository

Map existing CI/CD, task stores, observability, security, backup/recovery, architecture and agent instructions to framework semantics. Reuse working mechanisms; do not create shadow stores or duplicate policy merely to match framework filenames.

## Midstream active coding

Snapshot the real current state first. Preserve existing edits and evidence. Separate pre-adoption work from remaining work and from newly required verification. Never retroactively claim that earlier work was reviewed/authorized under the framework. Continue only after reconciliation and the required current authorization.

## Portable bundle boundary

The drop-in bundle includes canonical policy, schemas, verification/production routers, skills, workflow/bootstrap/supervisor prompts, templates, agent-facing adoption docs and deterministic runtime scripts. It excludes operator-only docs, external research and long reader/history artifacts so the coding agent does not pay permanent context cost for them.
