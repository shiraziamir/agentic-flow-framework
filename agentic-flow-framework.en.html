Core idea

Durable project memory; disposable, high-quality working context.

Keep tasks, evidence, decisions, architecture history, usage and execution history durable while loading only the current working set into ordinary agent sessions.

Risk-adaptive governance

LevelUse forFlow
HIGHArchitecture, persistence, production/security/trust, durable data, major public contractsDraft → supervisor → freeze → separate apply → execute → evidence → independent closure
MEDIUMBounded same-task correctionOwner-approved amendment → bounded apply → tests/evidence → independent closure
EVIDENCE_ONLYDocs/evidence/test-contract correction with no new runtime authorityDurable approved amendment + hash/ref → update → closure check if material

Source-of-truth, durable identity, STOP-before-scope-creep, no self-certification, no Task N+1 absorption, and “do not invent missing evidence” remain invariant.

Token and model efficiency

T0 deterministic/mechanical
T1 cheap read-only discovery/partition
T2 standard bounded execution
T3 judgment/high-risk review

Cheap workers may gather evidence only when the same acceptance quality can be preserved. token-efficiency warns on unjustified whole-repo scans, repeated rereads, full-history loading, huge raw logs, expensive models doing mechanical work, overlapping subagents, repeated failed loops, and budget overruns.

Observable usage may be recorded with schemas/USAGE_EVENT.md and scripts/usage_ledger.py. Unknown provider telemetry stays unknown rather than being guessed. Prompt caching may reduce cost/latency but is not assumed to reduce context occupancy.

Hot state vs cold history

Hot: current task/amendment, checkpoint/index, current budget/unresolved decisions, relevant modules/docs/skills. Cold: completed tasks, evidence, judgments, decisions, usage ledger, execution ledger, retrospectives, timeline and stories. Cold history is opened only for provenance, audit, regression, retrospective, storytelling or explicit user request.

Supervisor model

A supervisor may be a human, separate model or cold session. Direct-access review inspects actual source/diff/tests. Evidence-only review uses a bounded evidence packet and marks inaccessible claims UNVERIFIED_FROM_PACKET. Expensive review results are stored as compact decisions, not transcripts or private reasoning.

Formal execution retrospective

Long campaigns can maintain .agentic/history/EXECUTION_LEDGER.jsonl, a compact append-only boundary ledger defined by schemas/EXECUTION_RETROSPECTIVE_LEDGER.md. It records review, amendment, freeze, apply, STOP, evidence-ready and closure boundaries as short counters and references, never raw transcripts or duplicated evidence.

The cold project-retrospective skill can reconstruct timeline, task/amendment/review/STOP metrics, pre-closure defects, false-complete states prevented, implementation versus governance commits, test evolution, mutation/provider/token accounting where observable, deferred findings, governance overhead and process evolution.

Incomplete early history stays incomplete; exact historical numbers are never fabricated.

Storytelling and self-branding

project-storytelling is separate from audit reconstruction. It turns proven/reconstructed history into architecture narratives, case studies, lessons learned and portfolio/self-branding content. When a retrospective exists, storytelling consumes that bounded report first instead of rereading the entire archive.

Documentation freshness

Canonical/index/retrospective/story docs are versioned and timestamped. Material verified changes run documentation-freshness: update the authoritative source first, then synchronize reader views and generated adapters.
