# Agent instructions for this repository

This repository is the authoritative home of Agentic Flow Framework. The old Google Drive folder is archival only.

## Read order

1. `ARCHITECTURE.md` — canonical source of truth.
2. `schemas/TASK_CONTRACT.md` and/or `schemas/EVIDENCE_PACKET.md` when relevant.
3. `skills/00_INDEX.md`; load only the skill bodies whose triggers actually fire.
4. Only the research/template/bootstrap file relevant to the task.

Do not preload both HTML renderings or the full skill shelf.

## Authority

- Canonical architecture/policy: `ARCHITECTURE.md`.
- Durable data contracts: `schemas/`.
- Portable procedures: `skills/`.
- `agentic-flow-framework.en.md` and HTML files are explanatory/rendered documentation, not higher authority than `ARCHITECTURE.md`.
- `research/` stores source-grounded research notes, not independent policy.
- `templates/` are examples.
- Vendor-specific files generated by `prompts/bootstrap/` are adapters and may not override canonical policy.

## Update discipline

- Keep this root instruction file concise; it is a map, not the framework manual.
- One concept should have one primary home. Link instead of duplicating long policy.
- For material framework changes, use current primary sources and distinguish verified facts from recommendations.
- Preserve RTL for Persian prose and LTR for code, commands, paths, identifiers, YAML and URLs.
- Do not claim model/tool behavior from memory when current vendor documentation can verify it.
- Do not equate observed skill/model-route association with causality without controlled comparison.
- Do not make a reviewer mutate the work it is judging in the same review pass.
- Do not silently amend frozen task scope/strategy during APPLY.

## Repository mutation

Keep changes scoped. Do not add raw agent transcripts, secrets, chain-of-thought, generated build artifacts, or large log dumps. Research receipts should be links plus concise findings, not copied vendor documentation.
